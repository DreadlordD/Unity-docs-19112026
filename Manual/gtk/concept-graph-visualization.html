    Introduction to graph visualization

    Understand how visualization contexts display visual feedback, such as node progress, on a graph.

    Graph visualization displays visual progress indicators on the graph canvas at runtime. Use it to show which node your tool is evaluating and how far that node has progressed.

    A visualization context owns these indicators. You create a context for a graph, apply the indicators through references to individual nodes, and release the context when the run is complete. Because the context owns everything it applies, you can remove all the feedback at once rather than track each change.

    This page covers the concepts behind graph visualization only. For information on how to display progress on a node, refer to Display progress bars on nodes.

    Visualization contexts

    A visualization context is the entry point for graph visualization. To create one, call Registry.CreateVisualizationContext with the identifier of the graph you want to annotate, which is available from Graph.ID.

    For a node inside a nested graph, pass the identifier of the root graph rather than that of the nested graph.

    A context doesn’t modify the graph. It holds a separate layer of visual data that Unity draws over the graph canvas, so nothing you apply through a context saves to the graph asset.

    You can create a context before the Graph window opens. The context stores the values you set and applies them when a graph canvas becomes available.

    Node references

    A context doesn’t expose nodes directly. Instead, call Context.GetNodeReference with a node identifier, available from INode.ID, to get a NodeReference for that node. Use the reference to set, read, and clear the feedback on that node.

    A NodeReference is only meaningful to the context that produced it. If the identifier no longer matches a node in the graph, for example because the user deleted the node, Unity discards the stored visual data and ignores the call instead of throwing an exception.

    The context lifecycle

    A context implements IDisposable and keeps its visual data until you release it. When you dispose of a context, Unity removes every visual that the context applied to the graph.

    To reset the feedback between runs and keep the context, call Context.ClearAllVisualization instead. This removes the visual data but leaves the context valid so you can set new values.

    When you enter or exit Play mode, Unity releases every visualization context for every graph. Create your contexts after the mode change, and don’t reuse a context from before it.

    To hide the node feedback but not discard it, set Context.NodeCustomizationEnabled to false. Unity preserves the values you applied and restores them when you set the property back to true.

    Ways to set the progress fill

    There are two ways to set the progress fill on a node, and they differ in which object owns the value:

    • Node.FillAmount sets the fill directly on the node. This is the shorter option when you already have the node and you don’t need a visualization context.
    • NodeReference.FillAmount sets the fill through a context. The context owns the value, which means you can clear it along with all other feedback or hide all of it at once.

    Unity doesn’t save either property to the graph asset. For feedback that represents a run in progress, prefer a context, because when you dispose of the context, the graph returns to its default appearance.

    Note: The INode interface also declares a FillAmount property, but it throws a NotSupportedException. Use Node.FillAmount or NodeReference.FillAmount instead.
