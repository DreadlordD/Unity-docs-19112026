    Display errors and warnings on graph elements

    Report errors and warnings on the graph elements that caused them.

    When you log a message and pass a graph element as the context, Unity displays a marker next to that element in the Graph window. The marker points users at the element they need to fix, rather than leave users to match a console message against their graph.

    Unity also writes every message to the Console window but only while the graph’s editor window is open. If the window is closed, the message doesn’t appear anywhere.

    This page covers how to attach messages to specific graph elements only. For information on when Unity runs your validation code, refer to Introduction to the Graph Processor.

    Prerequisites

    Before you display errors and warnings on graph elements, you need a graph class. If you haven’t created a graph tool yet, follow the instructions in Implement a graph tool.

    Log a message on a graph element

    To display a marker on the element that caused a problem:

    1. Override Graph.OnGraphChanged in your graph class. Unity calls this method after every change to the graph.
    2. Identify the invalid element. For example, iterate the nodes returned by Graph.GetNodes.
    3. Call GraphLogger.Log, GraphLogger.LogError, or GraphLogger.LogWarning, and pass the element as the second argument.
    [Serializable]
public class ConnectionValidatedGraph : Graph
{
    public override void OnGraphChanged(GraphLogger graphLogger)
    {
        foreach (INode node in GetNodes())
        {
            for (var i = 0; i < node.InputPortCount; i++)
            {
                IPort port = node.GetInputPort(i);
                if (port.IsConnected)
                    continue;

                // Pass the node as the context to put a marker on that node.
                // Without a context, the message only reaches the Console.
                graphLogger.LogWarning($"Input port '{port.DisplayName}' isn't connected.", node);
            }
        }
    }
}

    Unity displays a marker next to the element and writes the message to the Console window. If you omit the second argument, the message reaches the Console window only and no marker appears.

    Unity recognizes the following types as a context:

    • Node and INode
    • State and IState
    • SelfTransition
    • Condition

    If you pass any other type, Unity attaches the message to the graph itself rather than to an element, so no marker appears. This fails quietly, so check the type when a marker doesn’t show up.

    Note: Don’t modify the graph inside OnGraphChanged because it can cause instability or recursive updates.

    Note: State machines use the same pattern. Override StateMachine.OnStateMachineChanged, and log through the StateMachineLogger that Unity passes to it.

    Choose a severity

    Use the severity that matches what the user needs to do about the message.

    Method Use it when
    LogError Unity can’t recover or proceed normally. The user has to fix the problem.
    LogWarning Unity can proceed, but there are side effects the user might not be aware of.
    Log The message contains information that’s not critical.

    All three methods take the same arguments and place a marker when you pass a context.
